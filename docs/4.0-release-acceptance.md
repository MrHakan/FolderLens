# FolderLens 4.0 release acceptance

This checklist separates automated checks from tests that need a real Windows
machine or network share. Keep the 4.0 version and release tag unchanged until
the field checks below have evidence.

## Automated coverage

GitHub Actions runs the unit and GUI suites on Windows and Linux. GUI coverage
includes the Explore layout at Tk scaling values of 125%, 150%, and 200%.
The Windows package workflow builds and smoke-tests both executable layouts,
tests the updater swap from the published v3.4.0 executable, and installs,
runs, and uninstalls the Inno Setup package.

These checks do not replace measurements on the target storage devices, an
actual SMB share, or visual inspection on a scaled Windows desktop.

## Local disk measurements

Create each corpus once on the Windows test machine:

```powershell
python benchmarks/create_dataset.py C:/test-data/files-10k --files 10000
python benchmarks/create_dataset.py C:/test-data/files-100k --files 100000
python benchmarks/create_dataset.py C:/test-data/files-1m --files 1000000
New-Item -ItemType Directory -Force C:/bench | Out-Null
```

For every corpus, run five v3.4.0 baseline scans and five candidate scans on
the same host, Python version, path, Defender setting, and cache condition.
Repeat separately for warm and cold cache. Save reports outside the corpus;
the commands and comparison format are in the project README.

The 1M local comparison reports whether both median scan time and median peak
RSS are at or below 75% of the v3.4.0 baseline. Treat those as candidate
targets, and require all runs to complete with matching item and inaccessible
counts before reviewing the measurements as comparable.

## SMB share checks

- [ ] Copy the unchanged 10k, 100k, and 1M corpora to the share and record its
  measured RTT and bandwidth.
- [ ] Compare five warm-cache and five cold-cache scans per version using the
  same share path, account, host, and Defender state.
- [ ] Confirm the item and inaccessible counts match. Review the report's
  network scan regression flag and inspect first-result latency separately.
- [ ] With the share, access, and cancellation cases, confirm a failed or
  disconnected scan ends as partial or cancelled without freezing the UI.

## Windows visual check

- [ ] On a real Windows display, inspect Explore at 125%, 150%, and 200% scale.
- [ ] Check the tree, treemap, and details pane at wide and narrow window sizes.
- [ ] Select a tree row outside the current map zoom, then drill in, go back,
  and select a map tile. Confirm the paired selection and details remain clear.
- [ ] Save screenshots and note the Windows display scale and resolution.

## Upgrade path

The public v3.4.0 release contains a standalone executable and a zip, but no
Setup installer. The automated update-swap test therefore covers the actual
published executable; it cannot test upgrading an installed v3.4.0 Setup
package. If an older Setup package becomes available, add its installed
upgrade/uninstall path before release. Settings migration is covered by a
legacy-format unit test.

## Release decision

Do not set `version.py` to 4.0.0 or create the v4.0.0 tag until the local disk,
SMB, and Windows visual checks above have recorded results and have been
reviewed. The scan harness and deterministic dataset generator are in
`benchmarks/`.
